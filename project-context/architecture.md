# SecureBuddy Architecture

## High-Level Architecture

```text
User
 │
 ▼
Telegram
 │
 ▼
Telegram Bot
 │
 ▼
Backend API
 │
 ▼
BullMQ Queue
 │
 ▼
Workers
 │
 ▼
MongoDB
 │
 ▼
Telegram Response
```

---

# Core Components

## Telegram

Responsibilities:

* User interface
* Identity provider
* File delivery channel
* Notification channel

No separate web frontend exists during MVP.

---

## Backend API

Technology:

* Node.js
* Express.js
* TypeScript

Responsibilities:

* User creation
* Credit validation
* Job creation
* Queue management
* Report management
* Sandbox session management

---

## MongoDB

Stores:

* Users
* AnalysisJobs
* Reports
* SandboxSessions

ODM:

* Mongoose

All schemas use:

```ts
{
  timestamps: true
}
```

---

## Redis + BullMQ

Responsibilities:

* Background jobs
* Retries
* Scheduling
* Worker coordination
* Job status tracking

Queue Examples:

```text
url-analysis
document-analysis
zip-analysis
apk-analysis
sandbox-creation
```

# Docker

Docker is a core security component.

All analysis executes inside disposable containers.

Examples:

## URL Analysis

```text
Worker
  │
  ▼
Docker Container
  │
  ▼
Playwright
```

## APK Analysis

```text
Worker
  │
  ▼
Docker Container
  │
  ▼
JADX + APKTool
```

## APK Streaming

```text
Worker
  │
  ▼
Docker Container
  │
  ▼
Android Emulator
  │
  ▼
noVNC
```

Container Lifecycle:

```text
Create
  │
  ▼
Analyze
  │
  ▼
Generate Report
  │
  ▼
Destroy
```

Containers must never be shared across users.

# Workers

## URL Analysis Worker

Tools:

* Playwright

Responsibilities:

* Open URL
* Capture screenshot
* Detect redirects
* Extract metadata
* Collect security findings

Workflow:

```text
Open URL
   │
   ▼
Capture Screenshot
   │
   ▼
Extract Metadata
   │
   ▼
Generate Findings
   │
   ▼
Send Screenshot To Telegram
   │
   ▼
Delete Screenshot
```

---

# AI Layer

Provider:

* Gemini API

Gemini is used only after deterministic analysis is complete.

Workflow:

```text
Worker
   │
   ▼
Raw Findings
   │
   ▼
Gemini
   │
   ▼
Summary
Risk Explanation
Recommendations
```

Gemini does not replace security analysis.

Gemini explains findings generated by workers.

---

# File Handling Strategy

Files are not permanently stored.

Workflow:

```text
Telegram
   │
   ▼
Worker Downloads File
   │
   ▼
Analyze
   │
   ▼
Store Report
   │
   ▼
Delete File
```

Only reports and metadata are retained.

---

# Screenshot Handling Strategy

Workflow:

```text
Playwright
   │
   ▼
Generate Screenshot
   │
   ▼
Send To Telegram
   │
   ▼
Delete Screenshot
```

Screenshots are not stored permanently during MVP.
